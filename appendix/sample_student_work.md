# Appendix C - De-Identified Student Work Records

This appendix provides de-identified, synthesized student-work records aligned to the ED452B rubric. These are not raw student documents. They are privacy-safe records showing the type of evidence the unit uses to interpret learning.

## Sample A - Strong Completion and Explanation

**Evidence observed:** Student planned the Agent's route, used an efficient sequence, and explained why a repeated movement could be represented with a loop.

**Rubric interpretation:**

- Followed directions: Meets
- Reached correct goal path: Meets
- Used efficient code: Meets
- Access supports used productively: Meets
- Explanation / reflection: Meets

**Teacher feedback:**

> You used efficient code and named why the loop helped. Next time, compare your loop to the longer version to show even more clearly how loops reduce repeated blocks.

## Sample B - Partial Success with Debugging Growth

**Evidence observed:** Student's Agent stopped one block short. During a teacher conference, the student counted the path again, identified the missing movement block, added one forward block, and retested.

**Rubric interpretation:**

- Followed directions: Meets
- Reached correct goal path: Approaching to Meets after revision
- Used efficient code: Approaching
- Access supports used productively: Meets
- Explanation / reflection: Approaching

**Teacher feedback:**

> You used debugging correctly: you compared what you expected with what happened, changed one block, and tested again. Next time, predict the number of forward moves before pressing Run.

## Sample C - Access Barrier Resolved Through Support

**Evidence observed:** Student initially clicked through the task without reading the NPC text and could not explain the goal. After using the NPC read-aloud card and task-goal restatement, the student built a partial sequence and orally explained the first two moves.

**Rubric interpretation:**

- Followed directions: Approaching
- Reached correct goal path: Needs support to Approaching
- Used efficient code: Needs support
- Access supports used productively: Meets after prompting
- Explanation / reflection: Approaching orally

**Teacher feedback:**

> Reading the goal first helped your code match the task. Next time, use the Stop-Read-Predict card before you press Run so you know what the Agent should do.

## Why These Samples Matter

These records show why the unit does not rely on completion alone. A student can demonstrate meaningful computational thinking through planning, debugging, oral explanation, and productive use of supports even if the final code still needs revision.
