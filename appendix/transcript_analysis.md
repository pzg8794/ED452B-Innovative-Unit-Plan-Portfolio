# Appendix B - Transcript Analysis

This appendix summarizes the TeachingPlacement transcript evidence used to revise the Minecraft Education Innovative Unit Plan.

## Privacy Note

This public repository does not include raw transcripts, student names, IEP documents, or identifiable student work. The analysis below uses de-identified patterns from the Grade 4 Minecraft lessons to support instructional planning.

## Core Finding

The major pattern was not simply that students struggled with coding. Students often struggled with access into the coding task.

That means the teacher had to distinguish among:

- interface or login barriers;
- reading and NPC-direction barriers;
- unclear task goals;
- executive-function and impulse-control barriers;
- collaboration or partner-role barriers;
- actual computational-thinking misunderstandings.

## Transcript Pattern Analysis

| Transcript pattern | Interpretation | Unit revision |
|---|---|---|
| Students skipped or did not fully process NPC directions. | Reading load and interface text affected access. | Add NPC read-aloud, printed direction cards, and goal restatement before coding. |
| Students misunderstood the two-gold-plate challenge. | The task goal was not visible enough before code execution. | Add visible success criteria and require students to restate the goal before Run. |
| Students needed hints such as counting spaces or remembering the Agent can float. | Students benefited from targeted hints that preserved thinking. | Add hints-before-rescue protocol and teacher conference prompts. |
| Students sometimes repeated the same coding error. | Debugging needed to be taught as a procedure. | Add Stop-Read-Predict-Run-Debug routine and debug logs. |
| Some students completed tasks but could not clearly explain why the code worked. | Completion and explanation are different learning outcomes. | Add exit tickets, oral conferences, and partner teach-back. |
| Some students had strong prior Minecraft knowledge. | Game expertise can be used as an asset. | Add Expert Helper roles and extension challenges. |
| Partner work sometimes needed clearer expectations. | Collaboration required explicit role structure. | Add Driver/Navigator cards and role switching. |

## Instructional Interpretation

The transcript evidence supports an assessment design that separates access from competence. A student who cannot enter the correct world independently may still understand sequencing. A student who completes the task quickly may still need support explaining the algorithm. A student who misreads the NPC text may need reading support, not a lower CS goal.

## How This Changed the Unit

The final unit was revised to include:

1. projected click-path routines;
2. NPC read-aloud and goal restatement;
3. planning before coding;
4. structured partner roles;
5. debugging as a visible routine;
6. multiple assessment sources;
7. target-student support plans;
8. explicit reflection on access and learning.

## Bottom Line

The transcripts turned the unit from a Minecraft activity into an inclusive computer science unit. They made it possible to identify what students were actually learning and what barriers had to be removed so that learning could become visible.
