# Appendix A - Assessment Tools

This appendix documents the assessment tools used across the Minecraft Education Innovative Unit Plan.

## 1. Startup and World-Entry Observation Checklist

| Item | Yes | With support | Not yet |
|---|---|---|---|
| Student logs in successfully. |  |  |  |
| Student reaches the correct Minecraft Education world. |  |  |  |
| Student opens MakeCode. |  |  |  |
| Student reads or listens to NPC directions. |  |  |  |
| Student can restate the task goal. |  |  |  |

**Purpose:** This separates access and navigation from computational-thinking evidence.

## 2. Plan Before You Code Worksheet

Students complete before longer sequences.

Prompts:

1. What is the goal?
2. Where does the Agent start?
3. Where should the Agent end?
4. What steps should the Agent take?
5. What do I predict will happen when I press Run?

## 4. Exit Ticket Sentence Frames

- Today I learned that an algorithm is...
- One bug I fixed was...
- My Agent did not do what I expected because...
- One support that helped me was...
- A loop helped because...

## 5. Driver / Navigator Role Card

**Driver:** Controls the keyboard and mouse. Explains before pressing Run.  
**Navigator:** Reads directions, checks the plan, asks questions, and watches for bugs.  
**Both partners:** Switch roles, explain one code choice, and respect the stuck protocol.

## 6. Expanded Unit Rubric

| Criterion | Meets | Approaching | Needs support |
|---|---|---|---|
| Followed directions | Restates the task goal and follows room directions. | Follows some directions but needs clarification. | Begins coding without understanding the goal. |
| Reached correct goal path | Agent reaches intended target or student revises effectively toward it. | Agent reaches part of the path or succeeds after substantial prompting. | Code does not yet connect to the goal path. |
| Used efficient code | Uses movement, turns, loops, or shortcuts effectively. | Code works but includes unnecessary blocks or inefficient pathing. | Code is mostly random or not yet planned. |
| Used access supports productively | Uses checklist, role card, NPC card, or planning sheet with independence. | Uses support after prompting. | Does not yet use available support. |
| Explanation / reflection | Explains one code choice, bug, fix, or efficiency decision. | Gives a partial explanation with frame or oral support. | Cannot yet explain the code choice, even with support. |

## 7. Feedback Bank

- "You improved when you stopped and predicted before running the code."
- "You used debugging because you changed one block and tested again."
- "Your Agent reached the goal, but now explain why the sequence worked."
- "The support helped you access the task; next time, try using it before asking for help."
- "You were a strong Navigator because you asked a question instead of taking over the keyboard."
