# Student Learning Analysis

## Analysis Question

The key question is not simply: Did students finish the Minecraft challenge?

The stronger question is:

> What computational thinking became visible once access barriers were separated from coding knowledge?

## Pattern 1: Startup and Interface Friction

Students needed support with sign-in, menu navigation, entering the correct world, and opening MakeCode. These barriers appeared before coding began. This means a student who was stuck early could not automatically be interpreted as lacking computational understanding.

**Instructional implication:** Startup independence should be observed separately from code accuracy.

## Pattern 2: NPC Directions and Task Interpretation

Students sometimes skipped or misread NPC directions. In the dual-gold-plate challenge, several students needed the goal restated: both the student and the Agent needed to stand on separate gold plates at the same time.

**Instructional implication:** The unit adds NPC read-aloud, goal restatement, and visible success criteria before coding.

## Pattern 3: Debugging Needed a Routine

When debugging was informal, students sometimes repeated the same mistake or changed code randomly. When the teacher asked students to count spaces, predict the Agent's route, change one block, and retest, debugging became evidence of learning.

**Instructional implication:** Debugging should be assessed as a process: expected outcome, actual outcome, one change, retest.

## Pattern 4: Collaboration Needed Structure

Some students benefited from peer help, but open partner work can allow one student to dominate. The Driver/Navigator roles make collaboration more equitable and observable.

**Instructional implication:** The teacher should assess both the code and the collaboration process.

## Pattern 5: Explanation Lagged Behind Completion

Some students could complete parts of a challenge before they could explain why their code worked. This matters because computational thinking includes explanation, not just successful movement.

**Instructional implication:** Exit tickets, oral conferences, and partner teach-backs are necessary evidence sources.

## Summary Claim

The unit shows that inclusive design shapes what becomes visible as learning. Students demonstrate stronger computational thinking when teachers reduce unnecessary barriers, make goals visible, structure collaboration, and treat debugging as normal programming work.
