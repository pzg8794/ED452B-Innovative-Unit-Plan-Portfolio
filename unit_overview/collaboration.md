# Collaboration

## Collaboration Sources

This unit reflects collaboration across several sources:

- cooperating teacher implementation and classroom routines;
- TeachingPlacement transcripts from the Grade 4 Minecraft lessons;
- student responses during Minecraft coding tasks;
- classroom challenge booklet expectations;
- ED452B rubric and course example structure;
- course readings on inclusion, assessment, and high-leverage practices.

## Cooperating Teacher Evidence

The cooperating teacher's enactment of the Minecraft lessons provided the most important design evidence. The transcripts showed where students became stuck, what clarifications helped, and which instructional routines needed to be made more explicit in the final unit plan.

## Student Collaboration

Students contributed to the unit design through their actual responses to the coding environment. Their patterns of misunderstanding, persistence, peer support, and explanation shaped the final supports.

Examples include:

- needing the dual-plate goal clarified;
- using hints to count blocks or rethink the Agent path;
- benefiting from peer support;
- needing structure so partner work did not become one student doing all the work.

## Future Collaboration Plan

In a full enactment, I would use a short collaborative debrief after each lesson:

1. Which students accessed the task independently?
2. Which students needed Tier 2 support?
3. Which supports were most effective?
4. Which directions or task goals caused confusion?
5. What should be revised before the next lesson?

This plan aligns with the rubric's collaboration requirement because it uses evidence from teachers and students to make instructional adjustments.
